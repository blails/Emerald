2. What information does Emerald process?

Depending on which commands and features are used or enabled, Emerald may process:

  • Discord identifiers: user, server, channel, role and message IDs.
  • Profile and membership details: usernames/display names, avatars, nicknames, roles and other member metadata needed by a feature.
  • Progress and activity: XP, levels, milestones, bump statistics, daily-use timestamps, economy balances, inventory, streaks and feature-usage counters.
  • Information you provide: reminder text and due times, saved embed templates, suggestions and optional birthday/time-zone settings.
  • Moderation and safety records: warnings, moderation cases, private staff notes, temporary moderation records and AutoMod violation details. An AutoMod record may contain up to 200 characters of detected message content.
  • Polls, giveaways and community activity: creator details, suggestion votes and participation references.
  • Server logs: when an administrator enables logging, Emerald may post event details to the configured log channel. Message edit/delete previews may contain up to 500 characters and relevant author/channel/message identifiers.

Emerald does not need to archive every server message to provide its features. Message content is read where required for enabled functions such as AutoMod, logging or commands that process text.

3. Why does Emerald use this information?

Information is used to provide Emerald's stated functions, including moderation and security, levels and rewards, economy features, reminders, birthdays, suggestions, polls, giveaways, support tickets and administrator-configured logging. The operator must verify that no additional deployed integration uses the data for a different purpose.

4. Where is information stored and who can receive it?

The reviewed source stores persistent records in JSON files under the bot's data directory and in a SQLite database. The Premium user list may also be stored in a separate JSON file alongside the bot program.

  • Discord: Emerald uses Discord's API to operate as a bot. Discord separately processes platform information under its own policies.
  • Hosting provider: the host may technically access bot files and databases while providing its service. The operator must identify the provider, region, access controls and backup arrangements.
  • Configured server channels: log entries and public community posts may be visible to people with access to those channels.
  • Other service providers: [REQUIRED: list any APIs, database, analytics, error-reporting or storage providers receiving Emerald data, or confirm none after checking the deployed configuration.]

Discord API Data must not be sold or used for advertising/data-broker purposes. Message content obtained through Discord APIs must not be used to train AI/ML models unless Discord has expressly permitted it.

5. How long is information kept?

The reviewed code includes a daily cleanup intended to remove warnings, moderation cases and AutoMod violations older than 30 days. Other records — for example levels, economy, reminders, templates, birthdays, suggestions and Premium usage — do not all have a separate automatic expiry in the supplied code.

Users can request deletion through /privacy. The command attempts to process Emerald's JSON files and SQLite databases and make a best-effort attempt to remove eligible bot-authored posts and log entries. The operator must separately document retention for hosting backups, server log messages and records outside Emerald's local files.

6. Your privacy choices and requests

Use /privacy in Discord to review the information Emerald may store and request deletion. The deletion action requires a second confirmation. Emerald reports when files, databases, posts, reactions or channels could not be processed.

The deletion command cannot remove:

  • Discord's own account, platform or service records;
  • messages you sent as a Discord user (use Discord's own controls where available);
  • screenshots, exports, or copies made by other people or other bots;
  • hosting-provider backups outside Emerald's live files; or
  • records the operator is legally required to retain, where applicable.

Using Emerald again after deletion may create new records when you use a feature again. You may also contact the operator at [PRIVACY EMAIL — REQUIRED] to ask about access, correction, restriction, objection or deletion where those rights apply.

7. Security

The reviewed application stores JSON and SQLite data and does not implement application-level encryption for those files. The operator must use appropriate host security, encryption at rest, restricted filesystem permissions, strong account security, secure backups and limited staff access. Bot tokens must be stored as environment variables or in a secret manager and must never be committed to source code or shared publicly.

If unauthorised access to Discord API Data is discovered, the operator must investigate, contain the incident and make notifications required by Discord's Developer Terms and applicable law.

8. Changes to this policy

This policy must be reviewed and updated whenever Emerald's data collection, storage, retention, sharing, hosting or deletion behaviour changes. The public page and the link configured in Emerald's user-facing information should remain current.
